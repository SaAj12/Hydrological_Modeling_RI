USGS Station Analysis Plan (Static PNGs for GitHub Pages)
=========================================================

Goal
----
Compute per-USGS-station “analysis” products from the existing discharge time series (and optionally precipitation),
save them as static PNG plots, and display them on the GitHub Pages site by loading the PNGs when a station is selected.

This plan describes WHAT analyses to do and HOW to do them. It does not run any analysis.


Inputs (already in this repo / pipeline)
---------------------------------------
1) Discharge time series (daily) for each USGS station:
   - docs/data/discharge_data.json (generated by: python scripts/export_discharge_data.py)
   - Key format: discharge_data.series[stationId] = [{date: "YYYY-MM-DD", value: <cfs>}...]

2) Optional precipitation for each USGS station:
   - pr_extracted/pr_<STAID>.csv (daily), already used for existing PNG precipitation plots.

3) Climate indices (monthly):
   - Stored as a small CSV table in the repo:
     - frontend/data/climate_indices_monthly.csv
     - docs/data/climate_indices_monthly.csv
   - Columns include: PNA, NAO, PDO, AMO, ENSO/SOI, MEI, AO (see template file).
   - These indices are joined to station-derived annual/seasonal metrics by year/season.


Outputs (static PNGs)
---------------------
Per station, write to BOTH:
  - frontend/images/usgs_analysis/
  - docs/images/usgs_analysis/

Proposed file naming (stable + easy to load from JS):
  - fdc_<STAID8>.png
  - pot_counts_annual_<STAID8>.png
  - pot_counts_seasonal_<STAID8>.png
  - seasonality_monthly_<STAID8>.png
  - extremes_topN_<STAID8>.png
  - precip_runoff_lag_<STAID8>.png            (optional, requires precip + event matching)
  - teleconn_counts_<STAID8>.png              (optional, requires climate_indices_monthly.csv)
  - teleconn_counts_summary_<STAID8>.png      (optional, requires climate_indices_monthly.csv)

Where <STAID8> is the 8-digit station id string (same padding rule used in the site).


Analyses to perform (per station)
---------------------------------
A) Flow Duration Curve (FDC)
   - What: Percent exceedance vs discharge to summarize the flow regime.
   - How:
     - Take all non-null daily discharge values.
     - Sort descending; compute exceedance probability p = rank/(N+1) (or rank/N).
     - Plot discharge (y, log-scale recommended) vs p (x, 0–100%).
   - Output: fdc_<STAID8>.png

B) POT Flood Frequency (counts)
   - What: Annual and seasonal counts of “flood events” using peaks-over-threshold (POT).
   - Why: Mirrors approaches in the papers you provided (POT + (quasi-)Poisson count modeling).
   - How:
     - Choose a station-specific threshold (decision):
       - Use the “target rate” method: choose threshold so average POT rate ≈ 2 events/year.
     - Identify events:
       - A day is an exceedance if Q(t) >= threshold.
       - Apply a “declustering” window so one storm does not count many times:
         - Use 14 days between peaks; within a cluster keep the maximum-Q day.
     - Count events:
       - Annual counts by water year or calendar year (pick one and keep consistent site-wide).
       - Seasonal counts (OND, JFM, AMJ, JAS or DJF/MAM/JJA/SON).
   - Outputs:
     - pot_counts_annual_<STAID8>.png
     - pot_counts_seasonal_<STAID8>.png

C) Flood Seasonality (timing)
   - What: Which months are flood-rich for the station.
   - How:
     - Use the POT event dates (from B) OR use annual peak dates (AMS).
     - Create a month histogram (12 bins) showing relative frequency of event months.
     - Optional: also show the “mean month/day of year” using circular statistics.
   - Output: seasonality_monthly_<STAID8>.png

D) Large floods summary (top-N)
   - What: Summarize “rare” events as in the large-flood literature.
   - How:
     - From annual maxima (one peak per year), take the top N events (e.g., N=10).
     - Keep all available years in the dataset, but let the plot axes naturally display/adjust within 2010–2025.
     - Plot: event rank vs discharge and annotate event dates (or a dot plot over time).
   - Output: extremes_topN_<STAID8>.png

E) Optional: Precipitation–runoff response
   - What: characterize response timing using your existing IMERG precipitation.
   - How (simple version):
     - Build daily precip series from pr_extracted/pr_<STAID8>.csv.
     - For each POT flood peak date, look back W days (e.g., 0–10) and compute:
       - cumulative precip and max 1-day precip.
       - lag = argmax correlation between precip and discharge anomalies in a short window.
     - Plot a small scatter: event peak Q vs event cumulative precip, and/or a lag histogram.
   - Output: precip_runoff_lag_<STAID8>.png

F) Optional: Teleconnection relationships (climate indices)
   - What:
     - Relate flood metrics (e.g., annual POT counts, seasonal POT counts, annual max magnitude) to
       climate indices like PNA/NAO/PDO/AMO/ENSO/MEI/AO.
   - Why:
     - Mirrors the “counts vs climate indices” approach in the papers you provided (Poisson/quasi-Poisson).
   - How:
     1) Prepare the climate indices table:
        - Use monthly index values, then aggregate to the same seasons you use for POT counts.
        - Example season blocks:
          - OND, JFM, AMJ, JAS (matches the site’s seasonal framing in some papers), OR
          - DJF, MAM, JJA, SON (standard climatological seasons).
     2) Compute the station response variables:
        - Annual POT count (from B)
        - Seasonal POT count (from B)
        - Optional: annual maximum discharge
     3) Model / association:
        - Start with a simple visualization: scatter of index value vs count (per year),
          plus a fitted line (Poisson GLM mean on count scale).
        - Use quasi-Poisson when overdispersed (common for flood counts).
        - Optionally test lagged indices (e.g., winter NAO lag-1 year) as described in some studies.
     4) Plot outputs:
        - teleconn_counts_<STAID8>.png:
          a multi-panel figure (e.g., 2x3) showing index vs annual POT count for selected indices (PNA, NAO, PDO, AMO, ENSO, AO).
        - teleconn_counts_summary_<STAID8>.png:
          a small “coefficient summary” bar chart (effect sign/magnitude) for the same station.


How to implement in this codebase (scripts + wiring)
----------------------------------------------------
1) Add a new plot script:
   - scripts/plot_usgs_analysis.py
   - Responsibilities:
     - Load station IDs from frontend/data/discharge_data.json (or docs/data/...).
    - For each station, load its discharge series and generate A–D (and E/F if enabled).
     - Save PNGs to:
       - docs/images/usgs_analysis/
       - frontend/images/usgs_analysis/
   - Dependencies: pandas, numpy, matplotlib

2) Add site placeholders in HTML (static IMG blocks), similar to existing precipitation blocks:
   - frontend/index.html
   - docs/index.html
   - Add a section under the discharge chart called “USGS Analysis” with <img> tags:
     - <img id="usgs-fdc-figure" ...>
     - <img id="usgs-pot-annual-figure" ...>
     - <img id="usgs-pot-seasonal-figure" ...>
     - <img id="usgs-seasonality-figure" ...>
     - <img id="usgs-extremes-figure" ...>

3) Update JS to load these PNGs when a USGS station is selected:
   - frontend/js/app.js
   - docs/js/app.js
   - Pattern matches existing precipitation/VTEC loaders:
     - base + "images/usgs_analysis/fdc_" + id8 + ".png"
     - base + "images/usgs_analysis/pot_counts_annual_" + id8 + ".png"
     - etc.
   - Also hide these blocks for NOAA stations and Sensors to avoid empty space.

4) Deployment:
   - Ensure docs/images/usgs_analysis/* is committed so GitHub Pages can serve it.
   - If you run scripts/prepare_gh_pages.py, note it replaces docs/images with frontend/images,
     so your analysis PNGs must exist in frontend/images/usgs_analysis/ as well.

5) Climate indices data maintenance:
   - Keep frontend/data/climate_indices_monthly.csv as the “source of truth”.
   - Copy/update docs/data/climate_indices_monthly.csv so it exists in the published site folder too
     (prepare_gh_pages.py will copy frontend/data/* by default).


Notes / choices you’ll need to decide once you’re ready to implement
--------------------------------------------------------------------
1) Year definition:
   - Calendar year vs Water year (Oct–Sep). Pick one and apply everywhere.

2) POT threshold selection (decision):
   - Use the “2 events/year” target-rate method for POT threshold selection.

3) Event declustering window (decision):
   - Use a 14-day declustering window.

4) Time span (decision):
   - Keep all available years (do not clip the data), but plots should be presented with x-axes that adjust naturally within 2010–2025.
     If a station has partial coverage inside that window, show whatever is available; if it has coverage outside, don’t force extra padding.

5) Alternative GitHub Pages integration approach (besides embedding many PNGs in the main page):
   - Add a separate “USGS Analysis” page (e.g., docs/usgs_analysis.html) that is dedicated to these figures.
     - Keep the main index lightweight (map + primary charts only).
     - On the analysis page, show the same USGS dropdown and then a scrollable set of figures (FDC, POT annual, POT seasonal, seasonality, extremes),
       with simple anchors (“FDC”, “POT counts”, etc.).
     - This reduces clutter on the homepage and avoids lots of hidden <img> blocks living in index.html.
